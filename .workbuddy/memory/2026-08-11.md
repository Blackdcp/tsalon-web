## 排查：后台"今天" 3.04M vs Codex ~100M+ 的采集缺口（tsalon token rank）

用户（github 154967851）在 08-10 19:21 投诉后台"今天"十几亿（已修复为 3.04M），现要求排查为何仍与 Codex 自身显示的 ~100M 不一致。

### 根因：时区分桶错位（主因）
- 站点侧"今天/周期"视图用 **UTC** 计算日期：`kv.ts` `getLeaderboard` line 328-331 (`new Date().toISOString()`)，
  以及 `updateTokenUsage` 增量分支 line 110 (`todayStr = new Date().toISOString()`)。
- 但 Codex token 上报 agent 把每日 history 的日期键写成 **用户本地时区（GMT+8）**。
- 证据：UTC 现为 `2026-08-10 17:28Z`，却已存在 `timeseries:2026-08-11` 的 codex 单事件 498,344,217（ts=2026-08-11 00:00:00，即 `new Date('2026-08-11')` 的本地键）。说明 agent 以本地"今天"=08-11 上报。
- 后果：站点的 UTC"今天"(=08-10) 读到的是 `timeseries:2026-08-10` = 3.04M（17 个 antigravity/workbuddy 事件，**零 codex**）；用户本地今天的 codex 498M 落在 `timeseries:2026-08-11`，UTC 00:00（=北京时间 08:00）之前站点"今天"读不到。
- 同时 `updateTokenUsage` 内部不一致：增量分支用 UTC today，history 分支用 agent 本地 dateStr。codex 走 history → 本地桶；其他工具走增量 → UTC 桶。

### 次因（待定，非本站 bug）：指标口径差异
- 站点 total = in+out+cache_read+cache_write（全量 token）；Codex UI 显示的"用量"可能是子集或不同口径。
- agent 上报 498M（本地今天 codex）vs 用户口述 Codex ~100M，约 5x，部分为口径差，不应急于当污染删。

### 结论
- 498M codex 事件是 agent 真实上报的本地今天用量，**不是污染**，不应删除（删了 UTC 翻日后"今天"又会缺失）。
- 真正要修的是**时区分桶一致性**：让站点"今天/周期"按用户本地时区算日期窗口（需 agent 上报 TZ，kv.ts line 110 / 328 改用本地日期）。否则每天 16:00 北京时间后的活动永远落在站点"明天"，"今天"恒低估。

## 2026-08-11 再续：用户问"昨天(08-10)为什么是 0"

### 诊断结果
- `timeseries:2026-08-10` 真实为空（0 events, dayTotal 0）——数据确实丢失，不是显示问题。
- **根因**：agent 间歇性把"终身累计量(~26.7B)"当单日值上报。historyData 路径的净化曾用 `hVal > 1B(ABSOLUTE_FLOOR)` 丢弃，把 08-10 这类"被报成累计"的日子直接变 0（08-09 因报了真实 ~946M 而存活）。仍是此前 agent 超额上报 bug，只是这次打到"过去天 restore"路径（之前只加固了 today 的 delta）。
- **更大问题（顺带暴露）**：profile total 26.7B vs 19 天 timeseries 之和仅 5.2B → **21.5B(≈80%) 用量没有按天归属**。agent 的 per-day historyData 稀疏/不可靠，7d/30d/90d 视图严重低估。

### 修复（用户拍板：改用累计快照差值）
- commit 04ca981（kv.ts，astro check 0 error）：
  1. **每日累计快照**：`updateTokenUsage` 每次上传存 `user:{uid}:device:{devId}:snap:{today}` = 该设备累计量（保留~120天）。累计快照可靠（today 的 275M/336M delta 已验证准确）。
  2. **快照差值归因（健壮路径）**：1.6 段扫描所有 device 快照，对连续两快照算 delta = 当日真实用量（免疫 agent 的飘忽 per-day history），仅回填 timeseries 为空的过去天，绝不覆盖已有好数据；按快照 delta 中位数×10（下限 2B）设日上限，拒绝 context-resend 幻影。
  3. **historyData 路径加固**：丢弃条件改为 `hVal<=0 || hVal>DAY_CAP || hVal>0.5*deviceTotal(累计转储)`，避免把累计当单日写 0；同时不再用已删除的 ABSOLUTE_FLOOR。
- commit dffaacb / a86ec69：db-maint2 加只读 `snapcheck` action（列快照键与推算的日 delta），验证快照机制。
- 已 push 并部署（a86ec69 live：snapcheck 返回 SNAPCHECK）。
