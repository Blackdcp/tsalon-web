## 修复4：Windows connect 命令又踩两个坑（commit 8fa70f5 / 构建 tsalon-gbd5g130c，已 promote）
- 坑 A（用户贴出的 `=16baf...` 报错）：旧 connect 命令是 `powershell -NoProfile -Command "$env:TSALON_TOKEN='<tok>'; iex (irm ...)"`。用户**已在 PowerShell 里**，外层 PowerShell 先把 `"$env:TSALON_TOKEN=..."` 里的 `$env:TSALON_TOKEN` 展开（当时为空）→ 内层收到 `='<tok>'` → 报"无法识别"。**嵌套 PowerShell 会展开 `$` 变量**。
- 坑 B（脚本 `$logPath:` 解析报错 `InvalidVariableReferenceWithDrive`）：`token-agent.ps1` 第 83 行 `"... Last lines of $logPath:"` 双引号里 `$logPath` 紧跟 `:` 被当成 PSDrive 限定符。改 `${logPath}:` 修掉。
- 修复：connect 命令改为**无 `$` 的单条命令**，PowerShell / cmd 都能跑：
  `powershell -NoProfile -Command "& ([ScriptBlock]::Create((irm 'https://www.tsalon.tech/scripts/token-agent.ps1'))) -token '<tok>'"`
  用 `[ScriptBlock]::Create(irm ...)` 把 token 当 **-token 参数**传入（脚本 `param([string]$token)`），彻底绕开 `$env:` 嵌套展开问题。en 版 connect 页旧的"下载到 TEMP\agent.ps1 再跑"也已换成同款（旧版会被 ExecutionPolicy 拦，正是 e17506c 修过的坑，en 页没同步）。
- **易复发提醒**：别再把 Windows 引导命令写成 `powershell -Command "$env:..."` 形式；也别在双引号字符串里写 `$变量:`（用 `${变量}:`）。

## 修复5：Windows agent.log 被另一进程锁 → 手动跑 node 没执行（commit f9b9594 / 构建 tsalon-ic19nt56l，已 promote）
- 现象：用户跑新命令后报 `out-file : 文件 agent.log 正由另一进程使用 … FileOpenFailure`，且 node 实际**没跑**（重定向 `*> $logPath` 独占开文件，旧计划任务正占用 → 重定向失败 → 原生命令未启动）。日志里 "Starting extraction…" 是另一个进程写进 agent.log、被 Get-Content 回显的。
- 根因：脚本 `& node … *> $logPath` 用 `*` 重定向（Out-File 独占打开）截断写同一文件；手动跑与计划任务（同一脚本）并发 → 锁冲突。
- 修复：改用 `[System.IO.File]::Open(path, Append, Write, FileShare.ReadWrite)` 开共享流 + `StreamWriter` 追加写，并把 node 输出 `2>&1 | ForEach` 同时写日志+回显到窗口；开文件失败重试 3 次（每次 500ms），仍失败则落到带时间戳的 `agent-<ts>.log` 兜底，保证手动跑永不因锁崩溃。计划任务每次 re-curl 同一脚本 → 之后也用共享写，不再互斥。
- 验证：线上 `token-agent.ps1` 含 `FileShare.ReadWrite` / `Open-LogStream` / `2>&1`。用户重跑后应通过。
- 旁注：用户这次数据其实已由旧计划任务自动上报（updatedAt≈16:45 北京，Black. 总 51.4B）；但其 claude 仅 47,537，偏低——Windows 上 Claude Code 用量确实小，或 jsonl 解析在 Windows 路径下未命中，需用户确认。
