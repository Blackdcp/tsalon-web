**平时用 Cursor、Claude Code 写代码，或者在终端跑多 Agent 任务的开发者，几乎都经历过这种尴尬时刻：** 正改到关键逻辑，终端突然弹出一行冷冰冰的 `You've reached your limit`，不仅打断思路，更让人抓狂的是——你根本不知道它到底什么时候能恢复。

是等 5 小时？还是到下周一才刷新？各大厂商有没有全服放水？群里流传的“官方发卡重置了”到底是真是假？

为了不再盲目猜时间、翻推特打听，我们开发了 [AI 配额重置雷达（WhenReset）](https://www.tsalon.tech/whenreset/)。这篇文章不堆砌虚词，带你把这套雷达的核心功能搞透，学会如何精准推算恢复时刻、稳住每周消耗节奏，并把重置提醒直接对接到团队的飞书或企微群里。

## 为什么大模型的额度恢复时间总是让人摸不着头脑？

**大模型厂商采用的滑动窗口与动态限额机制，让额度恢复时间天然具有非线性和不确定性。** 相比传统云服务“整点清零”或“月初扣费”的确定规则，AI 平台的额度管理往往存在以下几个实操难点：

1. **5 小时滑动窗口（Rolling Window）容易算错**：很多人以为“刚刚弹窗提示额度用光，那就等 5 小时后再来”。实际上，窗口起点是你这波调用的**第一条请求**发出的时刻。如果算错起点，你就会傻傻多等几个小时。
2. **全网全局重置与小范围发卡混为一谈**：厂商偶尔会因服务故障或产品更新，突然向全网所有账号执行全局重置（Global Reset）；但有时只是在论坛上向特定资格用户发放限量重置卡（Reset Cards）。很多开发者把发卡当成了全员解封，白白空欢喜一场。
3. **月初周初的扎堆并发潮**：当全网用户在周初集中解封时，接口往往会遭遇瞬间的高并发拥堵，哪怕额度显示充足，也容易频繁遇到超时与降级。

重置雷达的核心目的，就是通过持续汇集社区和官方验证过的事件，把这些暗箱里的规则变成透明的看板和数据流。

## 重置雷达到底在监测哪些模型和工具？

**重置雷达当前主要盯紧三大主力模型体系（OpenAI Codex、Anthropic Claude 与 xAI Grok），并在规划器中兼顾了 Cursor 等主流开发环境。**

在 [重置雷达页面](https://www.tsalon.tech/whenreset/) 顶部，你可以一键切换不同模型的专属面板：

- **OpenAI Codex**：追踪官方全局重置历史、受限测试范围调整以及社区验证的发卡记录，计算最近两次全局重置相隔的实际天数。
- **Anthropic Claude**：重点监控 Claude 3.5 Sonnet / Opus 相关的刷新脉冲与发卡规律，记录跨日与周度额度重置周期。
- **xAI Grok**：全新接入 Grok 平台的配额变动与重置事件，提供即时状态诊断与历史时间轴。
- **Cursor 等工具生态**：额度规划器内置了 Cursor 的 30 天计费预设（如 Pro 订阅的 500 次 Fast Requests）和通用的 7 天周度计费预设，方便多工具并用的工程师统一掌握进度。

每个面板上方都有健康指示灯与关键统计：历史重置了几次、上一次全网放水距今过了多少天、发卡记录有几条，一眼就能看清。

## 额度用光了？教你用 5 小时滚动计算器算出真正恢复时刻

**5 小时滚动恢复计算器的核心逻辑，是在你确认的窗口起始时刻上加上整整 300 分钟，帮你避免人肉加减算错时间。**

很多开发者误以为“触顶报警的那一刻”就是窗口起点，这是最普遍的认知误区。正确的使用姿势分为三步：

1. **找到当前窗口的第一条调用时间**：去模型控制台的历史记录、或者你的本地终端日志里，翻出这一轮密集调用中**最早发出的那条有效请求**的时间戳（比如今天下午 14:15）。
2. **输入已知起点时刻**：在计算器中输入该时间（支持跨日，例如昨天深夜到今天清晨）。
3. **获取推算恢复点**：计算器基于你确认的 5 小时滚动假设，换算出东八区（北京时间）的具体解封时刻并展示倒计时。

需要提醒的是：计算器是一个方便你在本地排期的辅助工具，它不会（也不可能）越权获取你的私有 API Key。各套餐具体规则如有变动，始终以平台控制台页面为准。

## 周初用太猛周中就断粮？如何用每周规划器稳住消耗步调

**每周额度规划计算器（Weekly Quota Planner）的核心价值，是帮你算出“今天最多还能烧多少额度”，防止在周期前半截把弹药打光。**

做大型重构或密集评测时，开发者很容易在周一、周二就把 80% 的配额消耗殆尽，剩下的几天只能干等。规划器用一个很务实的方式帮你踩刹车：

### 核心参数与算法

你只需要填入两个数据：
1. **当前已用百分比**（支持滑块拖动或精准数字输入，0% 到 100%）。
2. **周期重置时间**（默认定位到本周日 23:59，也可以点预设按钮一键切到 Cursor 30 天月度周期）。

系统会自动计算：

$$\text{每日建议安全预算} = \frac{100\% - \text{当前消耗百分比}}{\text{距重置还剩的天数}}$$

$$\text{预计周期总消耗} = \frac{\text{当前消耗百分比}}{\text{当前已过天数}} \times \text{总周期天数}$$

### 看懂四种健康状态徽章

- 🟢 **充裕 (Comfortable)**：消耗速度明显低于时间进度，额度绰绰有余，可以放心给重型任务开绿灯。
- 🔵 **稳健 (On Track)**：消耗步调与剩余天数相匹配，保持现在的节奏即可平安度过当前周期。
- 🟡 **紧张 (Tight)**：消耗偏快，剩余天数的日均预算已被压缩得很低，建议非核心改动换用轻量模型。
- 🔴 **预警超支 (Exhausted Early)**：按照目前的燃烧速度，额度会在重置日前提前耗光！计算器会直接推算出**预计哪一天哪一刻会彻底断粮**，提醒你提前收手。

填过的数据会自动存在浏览器的 `localStorage` 中，关掉网页下次再打开依然保留。

## 告别手动刷新：如何把重置提醒推送到飞书、企业微信与 RSS？

**靠肉眼每天刷网页看有没有放水太低效，把事件推流直接对接到团队日常办公群才是更省心的做法。**

### 1. 订阅实时 RSS 2.0 源

重置雷达对外暴露了标准的 RSS 2.0 端点，每次出现新的重置事件就会同步生成一条包含详情的更新：

- **中文订阅源**：`https://www.tsalon.tech/whenreset/rss.xml`
- **英文订阅源**：`https://www.tsalon.tech/en/whenreset/rss.xml`

你可以把它放进 Reeder、NetNewsWire，或者配置到 GitHub Actions 定时监听。

### 2. 飞书 (Feishu) 群机器人联动

在飞书群中添加一个“自定义机器人”，把 Webhook 地址拿出来，使用下面的轻量脚本即可推送卡片消息：

```javascript
// feishu-alert.mjs
const WEBHOOK_URL = process.env.FEISHU_WEBHOOK_URL;

async function sendFeishuAlert(provider, title, content) {
  const payload = {
    msg_type: "interactive",
    card: {
      header: {
        title: { tag: "plain_text", content: `🚨 AI 额度重置提醒：${provider.toUpperCase()}` },
        template: "blue"
      },
      elements: [
        {
          tag: "div",
          text: { tag: "lark_md", content: `**事件**：${title}\n**详情**：${content}` }
        },
        {
          tag: "action",
          actions: [{
            tag: "button",
            text: { tag: "plain_text", content: "查看雷达面板" },
            type: "primary",
            url: "https://www.tsalon.tech/whenreset/"
          }]
        }
      ]
    }
  };

  await fetch(WEBHOOK_URL, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(payload)
  });
}
```

### 3. 企业微信与钉钉接入

企业微信和钉钉的接入方式基本一致，直接构造标准 Markdown 消息体向机器人地址发起 POST 请求即可。

### 4. 浏览器系统级桌面通知

在雷达页面点击右上角的“开启桌面通知”，授权通过后，只要浏览器后台挂着这个标签页，系统检测到新重置就会通过操作系统通知弹窗提醒你，不会错过任何全服放水。

## 用雷达看额度，最容易踩的四个坑是什么？

**重置雷达是开发者互助与公共观测工具，使用时一定要分清它的能力边界：**

1. **别把“发卡”当“全员重置”**：看到重置卡事件，先看适用范围。许多发卡只是特定社区活动的限时优惠，不等于你名下的账号会自动多出额度。
2. **别拿“报错时间”当“窗口起点”**：推算 5 小时恢复时间时，一定要找这轮请求里最早的那次时间戳，切忌拿额度弹窗的时刻去算。
3. **公共看板查不到你的私人余量**：雷达观测的是全网宏观动向，查自己账号的具体剩余 Tokens / 额度，还得去厂商官网的后台。
4. **全网放水后的半小时往往最卡**：大范围重置发生后的 30 分钟内，全网都在同时发起请求，此时调用很容易偶发超时，建议稍微错开几十分钟再跑批处理。

善用雷达的时间轴、算清自己的安全预算、配合群机器人自动提醒，不管是日常编码还是跑多 Agent 任务，都能真正告别被突发限流卡住的被动。
